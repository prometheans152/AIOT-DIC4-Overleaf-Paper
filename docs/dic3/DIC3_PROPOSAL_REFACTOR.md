## 1. Abstract：A–F 六段式（約 500 字）

**A｜Attention Getter（動機）**　消費者在菜市場面對當下標價，往往難以判斷一週或兩週後的購買風險。臺中市政府公開 13 個公有零售市場每日蔬果均價，提供客觀的歷史訊號；然而，市場均價並非眼前商家的售價，且蔬菜價格具有顯著的持平與少數波動不均衡特徵。[D1]

**B｜But（挑戰）**　既有研究多預測批發或市場價格，部分應用支援當日買價比對或趨勢預報，但本案檢索範圍內未能確認已有完整結合「單店現價錨定、精確 7／14 日曆期限、同店到期 A／B 配對驗證」的可重現證據。不同交易層級、單位、缺測和資料發布延遲，使市場回測不能直接代表個店預測成效。[R01–R07]

**C｜Cure（解法）**　本研究提出 FMPA 領域分析代理人原型，讓使用者輸入今天的菜價、品項與單位；可選填同店同規格的上週價格，產生 A／B 兩種有明確限制的未來參考值。

**D｜Development（方法）**　使用臺中公開市場歷史、日期群組切分與防洩漏特徵，分別由 Random Forest、HistGradientBoosting 預測市場 7／14 天相對變化；ForecastEngine 計算結果，Web／MCP 工具返回資料日期與來源。LLM 僅負責工具選用和解釋，不得自行猜價。

**E｜Experiments（評估）**　首版封存測試分別含 2,085 與 1,859 筆市場觀測，比較全持平、動量和不變價基線；未來另依同店同規格到期實價配對驗證 A／B，補做資料異常與代理人安全情境測試。[E1]

**F｜Findings（結果與預期）**　目前 7／14 天方向 macro-F1 為 0.4218／0.4169，均低於動量基線 0.4226／0.4306；相對變化 MAE 也未勝不變價基線。現階段的貢獻是可追溯的市場實驗設計與低輸入原型，而非已驗證能替個店省錢。未來預期建立同店到期驗證資料與可檢驗的 Agent 安全評估；結果須待實測後報告。[E1]

## 2. Introduction：重新建立問題—證據—差異—貢獻鏈條

### A. Attention Getter｜為什麼值得做？

「今天高麗菜一台斤 32 元，下一週應先買、等候，還是只把它視為普通波動？」這個問題具有明確的時間、單位與決策主體。官方公開資料集 [D1] 記載 13 個臺中公有市場每日行情並將無報價記為 0（即缺測，不是免費）；其 2026 年詮釋資料仍持續更新。專案對首版三品項的可配對市場歷史統計發現，脫離預先定義 ±5%「持平」區間的比例：7 日為 **1,149／10,952＝10.5%**、14 日為 **1,773／10,680＝16.6%**。這是過去資料的樣本比例，**不是下次上漲機率，也不是個店風險**。少數非持平事件加上類別不平衡，使簡單 accuracy 容易掩蓋實際風險。[D1][E2]

### B. Background｜應用情境與領域背景

臺灣蔬菜流通涉及產地、批發、零售市場及個別攤商。批發價、公開市場均價與私人單店標價的生成機制、資料粒度均不同。消費者通常只有**當下單店售價**；店家、品種、規格、公斤／台斤換算、促銷與資料發布延遲都會改變比較意義。AI 技術可以估市場走勢，但實務上仍需要領域規則判定輸入可否比較、何時應回報資料不足。規範使用者查詢的時間點為臺灣日曆日 `t`，輸出必須對應 `t+7`／`t+14`，不可因公開資料晚幾日才公布而改成其他日期。[D1][R02][R04]

### C. Problem｜研究問題與驗證標的

- **RQ1（公開市場）**：日期嚴格切分後，市場相對變化的 7／14 日方向預測能否勝過同母體的簡單基線？**已有封存評估。**
- **RQ2（單店可用性）**：將市場變化錨定到今天單店價（A）、再加入同店上週價的固定調整（B），能否更接近**同店到期實價**？**尚待前瞻配對驗證。**
- **RQ3（領域代理人）**：是否能在維持來源、單位、截止日期、例外處理與不猜價的條件下，降低使用者查詢門檻？**已有工具與網頁原型，但尚待完整使用者與安全測試。**

### D. Existing Limitations｜現有工作的不足

**技術層**：序列模型可能捕捉趨勢，但價格持平占比高，僅比全持平模型好不足以證明實用；必須同時比較動量方向、零變化 MAE，以及高風險上漲類召回。**資料層**：批發預測精度不能推論零售店價精度；公開均價既沒有私人店 ID，也未必與使用者商品規格一致。**系統層**：市場查價或聲稱「AI 預報」的產品不一定公開訓練分割、可重現基線或真店到期驗證；文案未提及的功能一律標記 `UNKNOWN`，不宣稱其不存在。[R01][R05][R06]

### E. Innovation｜真正可檢驗的差異

本案不宣稱「樹模型比別人新」。設計重點是三個**可反駁**的假設：

1. **現價錨定**：`p_A(t+h)=p_store(t) × (1+r̂_market,h)`，保留使用者的單店價作金額起點，同時不混同公開與私人真值。
2. **可比私價的增量假設**：僅在同店、同品項、同規格、單位可換算且上週日期相距 `7±2` 天時，嘗試 `r_B=r_A+0.3×(Δ_store,7−Δ_market,7)`；`0.3` 是固定未訓練係數，不是已證明的最佳權重。
3. **同店前瞻配對協議**：在 `t` 同時凍結 A、B、資料版本與模型版本，於 `t+7`／`t+14` 收集同店實價；以同一批案例比較，避免把市場回測誤稱為個店驗證。

### F. Contributions｜已完成、待驗證分開

- **C1 已建立**：同日分組切分、標籤成熟清除與封存基線評估，負向結果可追溯；首版 RF／HGB 並未全面勝出。
- **C2 已實作規則、尚未驗證效益**：A／B 資料契約、單位與可比性判定，以及真店到期驗證方案；沒有可比較的真店到期樣本不能聲稱預測準確率。
- **C3 已有原型、待測人因與安全**：Web 和匿名 MCP 查價／預測工具可回傳標示來源與限制的參考結果；完整 LLM Planner、全面情境測試與購物效益仍需驗證。

## 3. Related Work：AI Technology × Domain Know-how

### 3.1 AI Technology｜研究方法與適用性（約一半）

臺灣蔬菜價格預測先前已比較 ARIMA、ETS、TDNN、LSTM 等方法，[R01] 將不同序列假設用於批發市場預測；[R03] 以 HHT 探討零售市場價格的非平穩特性；[R07] 使用氣象與蔬菜價格做決策樹資料探勘。鄰近的課程作品 Team17 [H17] 則以 LightGBM 整合批發交易與氣象資料預測五日價格。上述方法說明序列與樹模型是合理候選，**但不能用跨研究、跨交易層級的 R² 或 RMSE 去排名本案的三分類 macro-F1**。

**方法評議**：深度學習及集成樹模型可擬合交互作用，但價格黏著、稀有上漲事件和時間洩漏風險不會自動消失。模型應對同一封存期間的動量、零變化和全持平基線；比較時同時報告方向 macro-F1、相對變化 MAE、各類召回和資料分母。本案以驗證集選型、封存測試，不用最終測試回頭調參。[E1]

### 3.2 Domain Know-how｜從公開市場到消費者單店（約一半）

供應與天候可能影響批發價格，但傳導到各零售商的時間、幅度及品質／促銷條件並不一致。[R04] 利用電子發票研究零售層級，顯示零售資料需要自己的定義；[R02] 研究批發供應鏈私有紀錄的資訊增益，卻不是消費者同店買價。市場服務 [R05] 的官網已有短中長期 AI 趨勢文案，消費者應用 [R06] 也已提供輸入購買價與當日行情換算，故**不能**以「現有系統都只有歷史查詢」作為創新理由。

**領域評議**：市場均價、商家標價與到期成交價不可直接等號。台斤／公斤需以 `1 台斤＝0.6 公斤` 轉換；「一顆／一把」若無重量不可換算；公開資料 `0` 表示缺測，不作零元。B 模式若不同店／規格、時間超出 `7±2` 天或無可比公開同期行情，必須退回 A 並提示。所有使用情境都需顯示資料日期與假設，不承諾節省金額。[D1][R02][R06]

## 4. Deep Research｜5 核心思維、3 專業爭論、10 個深問題

### 4.1 Five Core Mindsets（5）

1. **M1 Comparability First｜先可比才分析**：店家、品項、品種與規格、同一計價單位必須可比。證據：[R02][R04] 顯示不同通路資料的角色不同。設計：B 需同店同規格、上週 7±2 天；不可比退 A。
2. **M2 Temporal Integrity｜防止未來資訊洩漏**：公開資料滯後且標籤需成熟。證據：本案日期分組與 1,386 列清除紀錄。[E1][E2] 設計：只用 t−1 前特徵，標籤 t+h+1 成熟，固定日曆期限。
3. **M3 Strong Baselines｜簡單模型是嚴格對照**：價格黏著時不變價與動量可能強於 ML。證據：7／14 天模型 macro-F1 低於動量、MAE 高於不變價。[E1] 設計：所有改良與完整同母體基線比，不只呈現 accuracy。
4. **M4 Public ≠ Private｜公開均價不是店價**：政府有市場日均價，沒有私人單店 ID。[D1] 設計：A 僅為錨定假設，店價驗證需要額外真店追蹤。
5. **M5 Error ≠ Utility｜預測分數不同於決策效益**：漏報上漲與錯誤建議可能成本不對稱。證據：本案 up recall 7 日 16／158，14 日 23／268。[E1] 設計：單列上漲召回、來源與限制，後續評估使用者是否真正受益。

### 4.2 Three Controversies（3）

**T1 市場均價可以當私人店價的基準嗎？**　觀點 A：市場共同供需訊號可提供方向參考（[R04]）；觀點 B：通路與個店標價有促銷、地點、品質等偏差（[R02]）。**共識**：可作假設而不能直接當個店真值。**未決**：不同市場聚合與同店實價之間的誤差，須前瞻配對測試。

**T2 複雜 ML 應取代簡單基線嗎？**　觀點 A：非線性模型可捕捉交互作用（[R01][H17]）；觀點 B：持平主導時簡單動量／不變價可能更穩健。**本案證據**：封存 RF/HGB macro-F1 和 MAE 均未全面勝出。[E1] **共識**：選型需同資料、同期限、同指標比較。**未決**：資料擴充和錯誤代價下的收益。

**T3 增加天氣或私人歷史是否一定值得？**　觀點 A：天候、供應和私人資料可能帶來訊號（[R02][R07][H17]）；觀點 B：取得成本、延遲、漏值和過擬合可能抵銷增益。**共識**：需要消融或配對評估。**未決**：B 固定 0.3 是否有效、氣象特徵的純增益及可遷移性；未經實驗不得下定論。

### 4.3 Ten Deep Questions（10；問題＋可驗證回答）

1. **Why：為何不只看 accuracy？** 持平占比高，全猜平可有高 accuracy 卻對上下漲零召回；使用 macro-F1 並列各類召回。[E1]
2. **What-if：如果最新公開行情晚於使用者今天五天？** 輸出仍是今天 t+7／t+14；註明資料時間與警告，若無足夠特徵就失敗，不把起點偷偷改成資料日。[D1][設計 §3]
3. **Trade-off：±5% 門檻改為 ±2% 會如何？** 事件數及誤報成本均會變；原門檻是先定義的研究選擇，敏感度分析尚未執行，不得臨時依測試調整。[E1]
4. **Failure：公開資料的 0 是否代表免費？** 否；官方定義為無報價，應視為缺測並避免當分母／訓練目標。[D1]
5. **Evidence：如何證明資料未洩漏？** 同日市場分組、特徵限制至 t−1、標籤成熟在 t+h+1，跨界未成熟 1,386 列清除；核對資料切分與程式。[E2]
6. **Comparison：Team17 R²=0.8061 是否優於本案 F1=0.4218？** 不能；前者價位迴歸、後者三類方向，任務、資料與分母不同。[H17][E1]
7. **Design Decision：為什麼 LLM 不直接計算價格？** 因需固定模型版本、日期及單位才能追溯；數值只由 ForecastEngine 回傳，LLM 不捏造工具缺值。[設計 §2][設計 §6]
8. **Real World：買一顆 30 元能與公斤價比較嗎？** 無重量不能。公斤轉台斤乘 0.6；需保留換算來源，避免店價錯位。[D1][設計 §4]
9. **Failure：上漲只抓對 16／158、23／268 時可當購物警報嗎？** 不可聲稱可靠；界面應展示限制，優先排定上漲類錯誤成本分析。[E1]
10. **Evidence／What-if：要如何裁決 B 比 A 好？** 事前同批凍結 A／B，收集同店同規格 t+7／t+14 的實際價；只比較有效配對樣本，缺值列未核對，不把公開市場回測冒充真店成功。[E2]

## 5. Proposed Scheme｜Agent 設計、流程與偽程式碼

### 5.1 System Architecture：八步驟編號與現況

```text
① User：蔬菜店／市場使用者的自然語言或 Web 表單
       │ 品項、今天正價格、單位、臺灣日期；上週同店價選填
       ▼
② Query & Validation：API/Web 欄位、日期、單位及可比性驗證 [CURRENT]
       ▼
③ Planner/Reasoning：選合法工具、整理回覆 [PARTIAL / 全面 Agent 評估未完成]
       ▼
④ Data Acquisition：臺中 13 公有市場每日行情、滾動推論歷史 [CURRENT]
       ▼
⑤ Analytics Engine：RF(7 日)／HGB(14 日) 估市場相對變化 [CURRENT]
       ▼
⑥ Domain Rules：A 現價錨定；Web 可比時 B 固定調整；缺測／過期警告 [CURRENT]
       ▼
⑦ Decision：每期限參考價、漲平跌、可用／不可用與限制 [CURRENT]
       ▼
⑧ Output：Web 或 MCP 兩工具回傳資料日期、來源、警示 [CURRENT]
       └── 任何來源／模型／參數不可用 → 明確失敗，不用 LLM 猜數字
```

**與根目錄 `design.md` 五群組的對應**：上圖 ①及③是舊設計①使用者／助理入口，②及④是舊②③ MCP／API 及⑤公開資料，⑤是舊④ ForecastEngine，⑥⑦⑧是舊③的結構化結果及沿原路回傳。**現有 MCP 只有 `get_market_quote`（需指定市場；只查行情）與 `post_forecast`（匿名 A，可用 `all_markets`）；`/records` 為 API，並非第三個 MCP 工具。**完整自主 LLM Planner、B/私人儲存於 MCP 均不得宣稱已實現。

### 5.2 Flowchart：輸入→處理→分析→判斷→輸出

```text
START
 ↓ 收取品項、今日店價、單位、今天 t、入口；上週價選填
 ◇ 必要資料完整且價格／日期／單位合法？ ──否──> 追問或拒絕，END
 是 ↓
 正規化元／台斤；確認市場或匿名 A 的 all_markets
 ↓ 取得 t−1 以前公開歷史／檢查缺測、模型工件、資料新鮮度
 ◇ 資料／模型可用？ ──否──> 回報來源／資料不足，不猜價，END
 是 ↓
 ForecastEngine 分別預測 7／14 日市場相對變化
 ↓（all_markets 時各期限獨立取 ≥3 個有效市場變化中位數）
 A＝今天店價 ×（1＋預測變化率）
 ◇ Web 有可比同店上週價與同期市場歷史？ ──是──> B 固定 0.3 調整
 否 ↓（只回 A）                             ↓
 合併輸出，按 ±5% 判斷漲／平／跌
 ↓ 標明 t+7／t+14、資料來源／日期、模式、限制／錯誤風險
 END
```

### 5.3 Algorithm 1｜FMPA 查詢（有行號 Pseudocode）

```text
Input : item, today_store_price, unit, t, market_id?, last_week_store_price?
Output: h∈{7,14} 的市場變化、A／可選 B 參考價、來源及限制
01  RECEIVE ① 的查詢；確認當日日期 t 與入口(Web/MCP)
02  VALIDATE ② 的品項、正價格、單位與日期；缺欄先追問，非法拒絕
03  NORMALIZE 換算元／台斤；MCP 預測未指定市場用 all_markets
04  RETRIEVE ④ t−1 以前的公開歷史；公開 0 視缺測，檢查價齡
05  IF 所需資料、模型或工具不可用 THEN 回報錯誤，不生成價格
06  FORECAST ⑤ 各 h∈{7,14} 的市場相對變動率 r̂_h
07  IF all_markets THEN 各 h 取至少 3 市場之有效 r̂_h 中位數
08  COMPUTE ⑥ A_h = today_store_price × (1 + r̂_h)
09  IF Web 且上週同店、同規格、7±2 天且同期行情可比 THEN
10      COMPUTE B_h = 今天價 × [1 + r̂_h + 0.3×(Δ店7日−Δ市場同期)]
11  CLASSIFY ⑦ 按變動率 r>+5% / r<−5% / 其餘持平；日期 t+h
12  RETURN ⑧ A／可用 B、期限、單位、資料日期、來源、警示及驗證邊界
```

**不變條件**：A 錨定是金額尺度轉換，若 `p_store(t)>0`，則 `(p_store×(1+r̂)−p_store)/p_store=r̂`；它不會因為換成店價錨點就提高市場方向分類準確率。B 的 0.3 係數不是從真店資料學得。公開過期先警告，但不能誤稱所有過期情況已硬拒；真正缺資料則不得補造。

## 6. Evaluation：已觀測與 Expected Outcomes 分開

### 6.1 既有公開市場封存測試（**實際結果**）

| 期限 | 模型／有效 n | 方向 macro-F1（模型／動量／全持平） | 相對變化 MAE（模型／不變價） | 上漲召回 |
| --- | --- | --- | --- | --- |
| t+7 | RF，2,085 | **0.4218／0.4226／0.3092** | **0.0664／0.0436** | **16／158＝10.1%** |
| t+14 | HGB，1,859 | **0.4169／0.4306／0.2954** | **0.0983／0.0748** | **23／268＝8.6%** |

測試母體為三種菜、臺中 13 市場的公開零售均價；範圍 2025-10-04～2026-10-02，依日期分區、以驗證集選型；兩期限樣本數不同。**macro-F1 沒有贏動量、相對變化 MAE 沒有贏不變價**。MAE 的單位是相對變化率，不是新臺幣，也不是個店準確率。公開歷史的後續滾動推論更新**不代表重訓，也沒有改寫封存評估**。[E1]

### 6.2 尚未完成的驗證（**Expected Outcomes，不寫假成績**）

- **真店配對實驗**：徵集同店／同品項／同規格的當日與上週價，當日同時凍結 A、B 及模型版本，於到期日回訪，記錄 `n_valid_pair`、缺測原因、方向 macro-F1、店價 MAE 與配對差值。預期得到**可判斷 B 是否真的有效的證據**，不預設 B 一定優於 A。
- **市場聚合驗證**：對 `all_markets` 的各期限有效市場中位數，另與單一市場與簡單基線在完全相同日及品項測試；**目前沒有其樣本外精度**。
- **代理人可靠性**：規劃包含單位混淆、無法換算的「一顆」、0 缺測、過時公開行情、API 失敗、無效市場／品項、B 跨店、來源缺漏與誘導 LLM 猜價格的情境；量測合法工具遵循、參數驗證、來源完整率、錯誤揭露與安全降級率。**尚未取得全面測試統計，不設定虛構 100% 達成。**
- **人因與決策實用性**：比較有／無來源與警告的介面，在理解、查詢負擔和錯誤信任上的差異。所有預期貢獻待正式實驗結果再寫成發現。
